# Notion 掲示板スキーマ

> Multi-Agent Team の唯一の業務通信チャネル（ADR-0005 ハイブリッド型）。
> 掲示板は **formal（開始指令 / 問題報告 / 完了報告）** と
> **informal（着手返答 / 進捗共有 / 質疑応答 / 議論）** の 2 層構造で運用する。
> 別 IM チャネル（Slack 等）の提案・新設は禁止。

---

## 1. データベース構成

### 1.1 推奨ワークスペース構造

```
Multi-Agent Team (Notion ワークスペース)
└── 掲示板 (親ページ)
    ├── 📋 Messages (Database)         ← 本スキーマの対象
    └── 📚 Tasks (Database, optional)  ← タスク台帳（後日検討）
```

最小構成では **Messages データベース 1 つで開始**。タスク台帳との分離は運用しながら
判断する（最初は 1 DB で十分）。

### 1.2 Messages データベースのプロパティ

| 名前 | 型 | 必須 | 説明 |
|------|----|------|-----|
| `タイトル` | Title | ✓ | `[TASK-NNNN] 短い件名` 形式（例: `[TASK-0001] Tech Lead 起用と初期スタック策定`） |
| `種別` | Select | ✓ | formal: `開始指令` / `問題報告` / `完了報告` ／ informal: `着手返答` / `進捗共有` / `質疑応答` / `議論` |
| `タスクID` | Text | ✓ | `TASK-NNNN` 形式（4 桁ゼロパディング）。informal の「議論」で特定タスクに紐づかない場合は空可 |
| `発信者` | Select | ✓ | `PM` / `Tech Lead` / `FE` / `BE` / `Mobile` / `QA` / `SRE` / `TechWriter` / `Researcher` |
| `受領者` | Select | △ | 同上。formal で必須。informal の「議論」（チーム宛）では空も可（ADR-0005 §5.3 の暫定運用） |
| `期日` | Date | △ | 開始指令で必須。それ以外は空でも可 |
| `優先度` | Select | △ | `P0` / `P1` / `P2`。開始指令で必須 |
| `ステータス` | Status | ✓ | `未着手` / `進行中` / `ブロック` / `完了` / `却下` |
| `親タスクID` | Text | △ | 関連する親タスクの ID（問題報告・完了報告・informal 4 種は親 = 開始指令の TASK-ID を入れる） |
| `成果物リンク` | URL | △ | 完了報告で必須。リポジトリ URL / PR URL / ドキュメント URL |
| `関連歴史メモ` | URL | △ | 重要な意思決定がある場合、`docs/history/*.md` への参照 |
| `投稿日時` | Created time | 自動 | 自動付与 |

### 1.3 Select 値の凡例

#### 種別

**formal（必須項目あり / 規律維持）**
- `開始指令` (色: ブルー)
- `問題報告` (色: レッド)
- `完了報告` (色: グリーン)

**informal（自由文体可 / 軽量）** — ADR-0005 で追加
- `着手返答` (色: イエロー / オレンジ系)
- `進捗共有` (色: グレー / ライトブルー系)
- `質疑応答` (色: パープル系)
- `議論` (色: ブラウン / ピンク系)

色は ADR-0005 マージ後に PM が後追いで Notion DB に反映する（実装は PM スコープ）。

#### 発信者 / 受領者
- `PM` `Tech Lead` `FE` `BE` `Mobile` `QA` `SRE` `TechWriter` `Researcher`
- 役職追加は PM が承認したタイミングでスキーマ更新

#### 優先度
- `P0` (色: レッド) — ブロッカー級。即時対応
- `P1` (色: オレンジ) — 通常優先
- `P2` (色: グレー) — 後回し可

#### ステータス
- `未着手` `進行中` `ブロック` `完了` `却下`

## 2. メッセージ本文（ページコンテンツ）テンプレート

各メッセージのプロパティに加え、ページ本文（コンテンツ）に以下のテンプレートで記載する。

### 2.1 開始指令

```markdown
## 背景
（なぜこのタスクを発行するのか。1〜3 行）

## 成果物定義
（具体的に何を作るか。ファイル名・URL・形式まで）

## 受入基準
- [ ] 条件 1（測定可能に書く）
- [ ] 条件 2
- [ ] ...

## 依存関係
- 前提となる別タスク: TASK-NNNN
- 必要な権限・アクセス・情報

## 補足
（必要なら）
```

### 2.2 問題報告

```markdown
## 事実
（何が起きたか。観測した事象を客観的に）

## 影響範囲
（どこまで影響するか。期日・他メンバー・成果物）

## 想定原因
（仮説。複数あれば箇条書き）

## 必要な支援
（誰に・何を・いつまでに）

## 期日影響
（このまま行くとどれだけ遅延するか）
```

### 2.3 完了報告

```markdown
## 成果物リンク
- リポジトリ: <URL>
- PR: <URL>
- ドキュメント: <URL>

## 受入基準の照合
- [x] 条件 1 — エビデンス
- [x] 条件 2 — エビデンス
- [ ] 条件 N — （未達。理由を明示し残課題に転記）

## 残課題
（未達項目・後続タスク候補）

## 学び
（再現可能な成功要因 / 失敗から得た教訓 / 歴史化対象なら docs/history/ への参照）
```

### 2.4 着手返答（informal）

タイトル: `[TASK-NNNN] 着手返答`。本文は 1〜数行で OK、敬体・常体どちらでも可。

```markdown
## 受領確認
TASK-NNNN を受領しました。

## 想定アプローチ（あれば）
- ステップ 1: …
- ステップ 2: …

## 着手見込み時刻 / 完了見込み時刻
着手: 14:30 JST / 完了見込み: 17:00 JST
```

### 2.5 進捗共有（informal）

タイトル: `[TASK-NNNN] 進捗: <短い動詞句>`。**判断・状態遷移の単位**で投稿（「30% 完了」のようなログ単位は禁止）。

```markdown
## 何が変わったか
（前提が変わった / 設計方針を変更した / マイルストーン到達 等）

## 理由
（簡潔に）

## 次のステップ
（あれば）
```

### 2.6 質疑応答（informal）

タイトル: `[TASK-NNNN] 質問: <主題>` または `[TASK-NNNN] 回答: <主題>`。

```markdown
## 質問
（仕様・受入基準・依存関係に関する不確実点を 1 件）

## 自分の暫定理解 / 仮説
（あれば。回答の高速化に寄与）

## 必要な回答品質
即答 / 数時間以内 / 翌日でも可
```

> 業務継続に支障が出るレベルの不確実性なら **問題報告へ昇格** すること（ADR-0005 §3.3）。

### 2.7 議論（informal）

タイトル: `[TASK-NNNN] 議論: <主題>` または、特定タスクに紐づかない場合は `[議論] <主題>`（タスクID 空）。

```markdown
## テーマ
（何を比較・検討したいか）

## 選択肢と評価軸
- 案 A: メリット / デメリット
- 案 B: メリット / デメリット
- 評価軸: コスト / トレーサビリティ / 拡張性 等

## 暫定の傾き
（強い意見を弱い保持で）

## 昇格候補か
- [ ] ADR 化を検討する
- [ ] 歴史化メモへ要約を残す
```

## 3. 命名規約

### 3.1 タスクID

- 形式: `TASK-NNNN`（NNNN は 4 桁ゼロパディングの連番）
- 採番: PM が開始指令発行時に採番。問題報告・完了報告は親の開始指令 ID を継承
- 連番管理: Notion DB 内のフィルタで採番、または PM が手動でインクリメント

### 3.2 タイトル

- 形式: `[TASK-NNNN] <短い動詞句>`
- 例: `[TASK-0001] Tech Lead 起用と初期スタック策定`
- 例: `[TASK-0001] 認証 API のレートリミット実装でブロック`（問題報告）
- 例: `[TASK-0001] 標準スタック ADR と次メンバー提案を完了`（完了報告）

---

## 4. 運用ルール

### 4.1 1 タスク = 1 開始指令 = 複数の問題報告/完了報告 + 任意の informal

- 同じ TASK-ID に対して問題報告は何回投げても良い
- 完了報告は通常 1 件。再オープンが発生したら新しい完了報告を出す
- informal（着手返答 / 進捗共有 / 質疑応答 / 議論）は親タスクID を必ず入れる
  （議論で特定タスクに紐づかない場合のみ空可）

### 4.2 ステータス遷移

```
未着手 ──▶ 進行中 ──▶ 完了
            │
            ├──▶ ブロック ──▶ 進行中
            │
            └──▶ 却下（途中で取りやめ）
```

- ステータスは **受領者が更新する**（PM が代行する場合は備考に明記）
- **「着手返答」を投稿した時点で受領者は親タスクのステータスを `未着手 → 進行中` に遷移させる**（ADR-0005 §2.5）。informal 4 種は親 formal のステータスを継承する形で運用する

### 4.3 投稿タイミング

| 種別 | 層 | いつ投稿するか |
|------|----|---------------|
| 開始指令 | formal | タスク発行時 |
| 問題報告 | formal | ブロッカー発生時、即時 |
| 完了報告 | formal | 受入基準の自己照合まで完了した時点 |
| 着手返答 | informal | 開始指令受領から 30 分以内 |
| 進捗共有 | informal | 判断や状態遷移が起きた時点（ログ単位の細かい更新は不可） |
| 質疑応答 | informal | 仕様・受入基準の不確実性を解消したい時 |
| 議論 | informal | 複数選択肢の比較が必要な時 |

進捗共有は **判断・状態遷移の単位** に限定する（「30% 完了」のようなログ単位は禁止）。

### 4.4 アーカイブ

- 月次で「完了」「却下」のメッセージを別ページにアーカイブ（任意）
- pptx レポート生成時は本 DB の全メッセージを集計対象とする

## 5. MCP 連携（Notion Remote MCP）

エージェントは Notion 公式の **Remote MCP** 経由で掲示板を読み書きする。
独自 API クライアントは原則作らない（決定経緯: `docs/history/2026-04-25_notion-mcp-adoption.md`）。

### 5.1 サーバ設定

リポジトリ直下の `.mcp.json` で登録済み:

```json
{
  "mcpServers": {
    "notion": {
      "type": "http",
      "url": "https://mcp.notion.com/mcp"
    }
  }
}
```

- トランスポート: HTTP（Streamable HTTP）
- 公式エンドポイント: `https://mcp.notion.com/mcp`
- 該当リポで起動した全 Claude Code（teammate を含む）が同じ MCP に自動接続

### 5.2 認証（OAuth）

Remote MCP は **OAuth 認証のみ**（bearer token 非サポート）。
各 Claude Code インスタンスでの初回セットアップ手順:

1. Claude Code 上で `/mcp` を実行
2. `notion` サーバを選択 → OAuth フローのリンクが表示される
3. ブラウザで Notion にログインし、ワークスペースへの認可を許可
4. Claude Code に戻ると認証情報が保存され、以降ツール呼び出し可能

OAuth 情報は Claude Code の認証ストアで管理されるため、`.env` にトークンを置く必要はない。

### 5.3 主要ツール対応表

| 操作 | MCP ツール（典型名） | 本PJ の使われ方 |
|------|---------------------|----------------|
| メッセージ投稿 | `create_page` (DB 配下) | 開始指令 / 問題報告 / 完了報告 |
| 受信箱確認 | `query_database`（フィルタ: 受領者 = self） | 担当タスクの取得 |
| ステータス更新 | `update_page_properties` | 未着手 → 進行中 → 完了 |
| 詳細閲覧 | `retrieve_page` / `retrieve_block_children` | 親メッセージ本文の確認 |
| 検索 | `search` | TASK-ID 横断検索 |

ツール名は MCP サーバ実装の更新で変わる可能性があるため、Claude が `/mcp` で
実際の利用可能ツールを確認してから使う。

### 5.4 環境変数

```
NOTION_BOARD_DATABASE_ID=<32文字hex>
```

DB ID のみ `.env` に設定。`NOTION_TOKEN` は Remote MCP では使わない（OAuth 管理のため）。

### 5.5 通知レイヤ

エージェントへの「メールあり」通知の実装方針は未確定。
`docs/history/2026-04-25_multi-agent-shogun-architecture-reference.md` §4 で議論した
4 候補（Notion API ポーリング / Webhooks / FileSystemWatcher / chokidar）の中から
Tech Lead が選定する。MCP は能動的な検知機能を持たないので、別レイヤが必要。
