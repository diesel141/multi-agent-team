## 5. 学び・python-pptx Tips

### 5.1 アジェンダレイアウト変更で気付いた点

- 当初の `card_w = 4.0`（3 列前提）を 4 列化する際、`card_w = 2.85, gap = 0.25, x0 = 0.6` で右マージン 0.58 inch（13.333 - 12.75）を確保。スライド幅 13.333 inch に対して 4 列収納の余裕値はこのあたりが上限
- カード内テキストは `card_w - 0.4` を幅にして余白を取る既存ヘルパーパターンを踏襲。テキスト幅 2.45 inch で 18pt 日本語 11 文字（"AI アシスタントツール"）が問題なく収まることを目視と座標計算で確認
- カードの num/en/jp/sub/terms の Y オフセットは card_h を変えていないので既存値をそのまま流用できた。**「縦は触らず横だけ広げる/狭める」設計**が 4 列化の最短距離だった

### 5.2 既存ヘルパーとの整合方法

`chapter_slide()` と `term_slide()` の引数は `(section_no, section_name, cat_color, ...)` のシグネチャで完全に統一されており、新カテゴリ 07 の追加は **既存呼び出し 1 つを参考にコピペ + パラメータ差し替え** だけで済んだ。色定数 SLATE を 1 つ追加し、`cats` 配列に 1 行追加し、章扉 + 用語スライドを 1 セット追加する、という機械的差分で完結。

### 5.3 Sanity check は python-pptx 再オープンが最速

PowerPoint で目視確認するより、生成直後に `Presentation(out)` で再ロードして全スライド数 / 各スライドのテキスト一覧を dump する方が速い。今回も 32 スライド存在 / slide30 章扉 / slide31 Claude Code / slide32 まとめ / アジェンダ 7 カード位置（行 0：x=0.6/3.7/6.8/9.9、行 1：x=0.6/3.7/6.8）/ 表紙「26 語」・アジェンダ「7 categories ｜ 26 terms」を機械的に確認した。

### 5.4 ターミナル文字化けに惑わされない

cp932/Shift-JIS でターミナル出力すると pptx 内の日本語が文字化けして見えるが、pptx 自体は問題ない（PowerPoint で開けば正常）。`print(repr(t))` で確認するか、`'語' in t` のようなマーカー文字で間接的に確認する習慣が安全。

#### 9.2.1 開始指令のスコープ誤訳

完了報告チェック時、pptx 構造（スライド数・配色・ヘルパー継承）の sanity check に注力し、**他用語スライドとの抽象度差**という用語集レビューで最も基本的な観点を見落とした。受入基準に「粒度規律」が項目として入っていなかったため、チェックリスト機械照合では検出されなかった。
