## 5. マージ判断軸の言語化

### 5.1 採用したフレーム
**「受入基準クリア × 8 論点判断確定」を Approve の必要十分条件とした**。
ADR ハウススタイル（auto memory `adr_house_style.md`）の軽微な漏れ（後述 §6）は
受入基準の外側で発見した品質改善ポイントであり、merge ブロッカーにせず
「next ADR から 100% 適用」とする運用判断。

### 5.2 採らなかった選択肢
- **「ハウススタイル違反を厳格に修正要求」**: 4 箇所漏れの修正 PR を Tech Lead に
  依頼してから merge する案。却下理由は「PM の役割は流れを作ること、書式の細部
  修正で TASK-0001 完了を遅らせる ROI が低い」（PM ペルソナ §11、アンチパターン §8）
- **「PM 自らが書式修正コミットを当てる」**: PM ペルソナ §8「メンバーの代わりに
  コードを書かない」アンチパターンに該当
- **再考の閾値（厳格修正フレームに転じる条件）**: 同様の漏れが ADR-0003 / ADR-0004 でも
  発生したら、修正要求を merge ブロッカー化する

### 5.3 判断の蓄積価値
本判断は「Tech Lead 着任直後の品質ゲートをどこまで律するか」の初期テンプレ。
**「ハウススタイル軽微違反は次 ADR で 100% 適用、本 PR は内容承認・即マージ」** を
採用したことで、後続 Tech Lead が同型の判断に迷わず済む。

## 8. なぜこれを残すか（歴史化の理由）

1. **PM の受入判断テンプレ**: 受入基準照合 + §5 論点判断 + ハウススタイル違反扱いの
   3 軸での判断パターンが、後続全 ADR レビューで再利用される
2. **「流れを止めない判断」のアーカイブ**: ハウススタイル軽微違反を merge ブロッカー
   にしない判断は、PM が「マイクロマネジメントしない」(PM ペルソナ §4) を実装した例
3. **8 論点の決着** が ADR-0001 / 0002 の運用解釈を固定する。後続 Tech Lead が
   「Vercel から離れていいか」「BE 即時起用は本当に承認されたか」等を毎回ゼロから
   議論しなくて済む
