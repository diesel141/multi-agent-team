## 2. 性質の昇格 — 事後追認 ADR から構造改善 ADR へ

これは ADR ハウススタイルの新パターン（「事後追認」と「構造改善」の判別基準）として記録対象。判別シグナルは「変更後の前提が、追認対象の条文を直接書き換える性質か」。

## 7. 学び（次回再利用可能）

1. **「事後追認」と「構造改善」の判別基準**: 開始指令発出後にユーザー回答で前提が変わった場合、事後追認では不整合になるなら構造改善に昇格させる。判別シグナルは「変更後の前提が追認対象条文を直接書き換える性質か」
2. **Superseded の粒度明示は必須**: 複数機能を持つ ADR は「§X.Y のみ」「§A は継続有効」と粒度を書く。粗い Superseded は他条文を巻き込む
3. **「見落としドメイン候補リスト」の効用**: ADR-0002 で Designer が抜けた構造的原因は「コードを書く職能だけ想定」の偏り。予備リストの恒久化が安価で効く
4. **権限境界 ADR にも採用案の再考閾値**: §6 で並列化することで ADR が「永続契約」でなく「現時点の合意」として機能
5. **PR レビュー&マージは Tech Lead が一気通貫で進められる**: 前段 PR が後段 PR の前提テンプレを含むケースは同一 Tech Lead セッションで連結処理する方がコンテキスト切替コストが低い
6. **テンプレライブラリ初実証**: PR #15 で整備した `docs/templates/instructions/_common-prologue.md` を参照する形式で TASK-0008 指示書本体が 80 行に収まった（従来 200 行）。テンプレ駆動は機能している
