## 1. Context（文脈）

### 1.1 ADR-0005 採択後の運用観測（2026-04-26 〜 2026-04-29）

ADR-0005 で **formal 3 種 + informal 4 種**（着手返答 / 進捗共有 / 質疑応答 / 議論）のハイブリッド型を採択した後、TASK-0006 〜 TASK-0020 にかけて以下が観測された:

1. **「ノイズ判定 50% 超」のロールバック閾値（ADR-0005 §4 却下 A 再考閾値）は未作動** — 進捗共有の細粒度乱発は実運用では発生していない
2. **歴史化トリアージ 18:00 リチュアルは数分単位で完結** — ADR-0005 §3.7 リスク 3「historization の手間増」は緩和策（PM ペルソナ §10）の範囲内に収まっている
3. **情報伝達の二極化が観測された** —
   - 業務外（チームビルディング / 雑感 / プロジェクト全体への所感）を残す場が存在せず、formal/informal どちらにも収まらない発話が **「議論」種別に擬似投稿** されるか、**Notion 外で消滅** している
   - ログ単位の進捗（「ファイル X 編集中」「30% 完了」）は ADR-0005 §2.2 で禁止されたが、実運用では **「状態遷移単位」の解釈が個人差で揺れ**、判断のオーバーヘッドになっている

## 2. Decision（決定）

### 2.1 採用案: 8 種化 + 進捗共有ログ単位許容

**Notion 掲示板を formal 3 種 + informal 5 種の合計 8 種で運用する。**

| 層 | 種別 | 必須項目 | 歴史化対象 | 投稿の重さ |
|----|------|----------|-----------|-----------|
| **formal** | 開始指令 | タスクID / 受領者 / 背景 / 成果物定義 / 期日 / 受入基準 / 依存関係 | ✓（要所） | 重い（規律維持） |
| **formal** | 問題報告 | タスクID / 事実 / 影響範囲 / 想定原因 / 必要な支援 / 期日影響 | ✓（要所） | 重い（規律維持） |
| **formal** | 完了報告 | タスクID / 成果物リンク / 受入基準の照合結果 / 残課題 / 学び | ✓（要所） | 重い（規律維持） |
| **informal** | 着手返答 | タスクID / 親タスクID（= 開始指令） | △（必要時に昇格） | 軽い（自由文体可） |
| **informal** | 進捗共有 | タスクID / 親タスクID | △ | 軽い（**粒度自由 / ログ単位も可**） |
| **informal** | 質疑応答 | タスクID / 親タスクID | △ | 軽い |
| **informal** | 議論 | タスクID（無関係なら空可） | △ | 軽い |
| **informal** | **雑談**（新規） | **なし**（タスクID・受領者すべて任意 / タイトルのみ必須） | ✕（原則） | 最軽量（業務外可・自由文体・短文） |

### 2.2 雑談（新規）の用途定義

- **対象**: 業務外の軽い発話 / チームビルディング / プロジェクト全体への所感 / 雑感 / 「ちょっと共有したい技術小ネタ」
- **必須項目**: タイトルのみ。タスクID・受領者・親タスクID は **任意**
- **SLA**: なし（応答義務なし）
- **粒度**: 短文・自由文体・絵文字使用も可（ただし **コミットメッセージ・ADR・歴史化メモ等の formal 文書では引き続き不使用**）
- **歴史化**: 原則対象外。万一「雑談」内で要所判断が成立した場合は **議論または ADR へ昇格** させる（投稿者または PM が判定）

### 2.3 進捗共有のログ単位許容（ADR-0005 §2.2 撤廃）

ADR-0005 §2.2 の「**進捗共有: 判断や状態遷移の単位で投稿する。「30% 完了」のようなログ単位禁止**」を **撤廃** し、以下に置き換える:

> **進捗共有**: 状況共有が必要な任意のタイミングで投稿してよい。「30% 完了」「ファイル X 編集中」等のログ単位投稿も許容する。判断・状態遷移の単位を強制しない。

### 2.4 informal の追加自由度

- 雑談の文体: 敬体・常体どちらでも可。絵文字・カジュアル表現可
- 雑談の長さ: 1 行〜数百行まで自由（ただし長文化したら議論または歴史化メモへの昇格を推奨）
- 雑談の受領者: 空（チーム全員宛）または特定ロール宛のいずれでも可
- スレッド構造: ADR-0005 §2.4 に準拠（独立ページとして投稿）

### 2.5 ロールバック閾値（採用案にも明示 / ADR ハウススタイル）

採用案の継続可否を判定する閾値:

- **2 週間運用後** に以下のいずれかが発生した場合、本 ADR を改訂し雑談を別 DB 分離（却下 (c)）または進捗共有ログ単位の上限件数導入（却下 (b)）を再検討する:
  - 雑談・進捗共有の合計が **掲示板全投稿の 70% 超** に達し、formal 受入照合の可読性が低下した（PM の朝会オペレーションで「formal のみ」フィルタを使っても認知負荷が増した）
  - PM の歴史化トリアージ 18:00 リチュアルが **45 分超** に常態化した
  - 雑談で要所判断が成立したのに議論／ADR への昇格漏れが **3 件以上** 発生し、トレーサビリティ低下が顕在化した

## 3. Considered Alternatives（却下した代替案）

### 却下 (a): informal 現行 4 種維持 + 雑談を「議論」に吸収

- **却下理由 1**: 「議論 = 複数選択肢の比較・トレードオフ言語化」（ADR-0005 §2.2 / docs/notion-board-schema.md §2.7）と「雑談 = 業務外の軽い発話」は SLA・期待値・歴史化判定が異なる。混在させると Tech Lead 視点で「これは ADR 候補の議論か、ただの雑感か」を区別できず、後の歴史化トリアージで PM の判断負荷が増える
- **却下理由 2**: ADR-0005 §4 却下 F「質疑応答と議論を統合」を却下したのと同じ論理。SLA / 回答品質の期待値が異なるものは別種別が適切
- **却下理由 3**: ユーザー指示は「雑談を解禁」と明示されており、「議論で代用」は規律変更ではなく現状維持に近い
- **再考の閾値**: 採択 1 ヶ月後に「雑談」種別の投稿頻度が **タスクあたり 0.5 件未満** に収束し、独立種別としての存在意義が薄れた場合 → 議論との統合を再検討

### 却下 (b): 進捗共有のログ単位を上限件数で制御（タスク日次上限 N 件）

- **却下理由 1**: ユーザー指示は「ログ単位制約の撤廃」であり、上限件数制御は実質的にログ単位禁止を別形式で復活させる。指示の趣旨に反する
- **却下理由 2**: 上限件数（例: 1 タスク / 日 5 件）の数値根拠が現時点で存在せず、現場判断で恣意的に運用されるリスクが高い
- **却下理由 3**: 「30% 完了 / 60% 完了 / 90% 完了」のような自然な進捗報告が上限超過扱いされ、心理的安全を毀損する
- **再考の閾値**: 採択 2 週間後に進捗共有が **掲示板全投稿の 50% 超** に達し、PM 朝会の認知負荷が増した場合 → タスク日次上限（例: 5 件 / 日）を導入
- **補足**: §2.5 採用案ロールバック閾値の 1 つとほぼ同条件のため、本却下案は採用案ロールバック時に最初に検討する候補となる

### 却下 (c): 雑談を別 DB に分離

- **却下理由 1**: ADR-0005 §4 却下 C「formal/informal を別 DB に分離」と同じ理由で却下。PM が掲示板を一望するためには 2 つの DB を行き来する必要があり、朝会のオペレーションコストが増える
- **却下理由 2**: タスクID で紐づける場合の cross-DB relation が不要になる利点はあるが、現状 Messages DB 単一の総ページ数は 100 件未満（ADR-0005 §4 却下 C 再考閾値「500 件超」未到達）
- **却下理由 3**: pptx レポートの集計対象が複数になり集約スクリプトが複雑化する
- **再考の閾値**: 単一 DB の総ページ数が **500 件超** になり Notion の検索パフォーマンスが体感で劣化した場合（ADR-0005 §4 却下 C と同条件）、または雑談だけで月間 100 件超に達し formal/informal の検索ノイズになった場合

### 却下 (d): 雑談を解禁せず別 IM チャネル（Slack 等）を新設

- **却下理由 1**: CLAUDE.md §9 アンチパターン「別 IM チャネル（Slack 等）の提案・新設」を直接違反する
- **却下理由 2**: ADR-0005 §1.5 で確立した「掲示板に通信を集約することで歴史化と pptx 生成の一次ソースを単一化する」原則を破壊する
- **却下理由 3**: ユーザー指示は「掲示板への投稿は『雑談』『進捗共有』も解禁」と明示されており、別チャネル提案は指示の趣旨に反する
- **再考の閾値**: 該当なし（永久に却下）

## 4. Consequences（帰結）

### 4.1 ポジティブ

1. **業務外発話の場の公式化** — チームビルディング / 雑感 / プロジェクト全体への所感を残す場が確保され、Notion 外で消滅していた情報が掲示板に残る
2. **進捗共有の心理的負荷低減** — 「これは状態遷移か / ログ単位か」の判断オーバーヘッドが消え、必要なときに必要な粒度で投稿できる
3. **トレーサビリティは維持** — formal 3 種の必須項目は不変。雑談・進捗共有のログ化が許容されても受入照合と歴史化の規律は崩れない（ADR-0005 §2.3 継続有効）
4. **ADR-0005 部分 Superseded パターンの再現性確認** — ADR-0008 で確立した粒度限定 Superseded 方式が ADR-0005 にも適用でき、組織規律 ADR の保守性が示された

### 4.2 ネガティブ・リスク

1. **掲示板のノイズ増加リスク** — 雑談・ログ単位進捗が大量流入し formal の可読性が低下する可能性
   - **緩和策**: §2.5 ロールバック閾値で 2 週間後に定量計測。閾値超過時は却下 (b)(c) 再評価
2. **歴史化トリアージ工数の増加** — 雑談から要所判断を拾う負荷が PM に発生
   - **緩和策**: 雑談は原則歴史化対象外（§2.2）。万一要所判断が混入したら投稿者または PM が議論／ADR へ昇格させる運用
3. **「雑談 → 議論 → ADR」昇格漏れリスク** — 雑談で重要決定が成立しても歴史化されない
   - **緩和策**: §2.5 ロールバック閾値で「昇格漏れ 3 件以上」を検知。検知時は雑談種別の投稿テンプレに「歴史化候補チェック」項目を追加
4. **進捗共有の解釈乖離** — ADR-0005 §2.2 を読んだ過去ロールと本 ADR を読んだ未来ロールで認知差が出る
   - **緩和策**: ADR-0005 §2.2 ヘッダに本 ADR §2.3 への参照を脚注追加（ADR-0008 が ADR-0003 §2.1 に行ったのと同パターン）

## 5. 開いている論点（PM 承認・議論で動かしたい点）

> 「**強い意見を弱い保持で**」。本 ADR は採用案を確定するが、各論には議論余地がある。

### 5.1 雑談の歴史化判定ルール

§2.2 で「雑談は原則歴史化対象外」「万一要所判断が混入したら議論／ADR へ昇格」と規定したが、昇格判定の主体（投稿者本人 vs PM 18:00 リチュアル）を明確化していない。当面は **両方の経路を許容** とし、運用 2 週間後に主導権を一本化するか判定する。

### 5.2 雑談の検索可読性

雑談の投稿頻度が想定を超えた場合、Notion view で「雑談を除外したフィルタ」を朝会オペレーション用に追加するかは PM 裁量。本 ADR では強制しないが、§2.5 ロールバック閾値（70% 超）に近づいたら追加すべき。

### 5.3 進捗共有のログ単位許容と PM 朝会の関係

ADR-0005 §3.2 で「PM 朝会は formal のみフィルタで未応答の問題報告と未受領の開始指令を確認」と定義済。本 ADR で進捗共有が増えても朝会オペレーションは不変だが、informal の「未応答質疑応答ピックアップ」が増える可能性は残る。1 ヶ月後に PM が朝会工数を再計測。

### 5.4 雑談の絵文字許容と「ADR / 歴史化メモは絵文字不使用」原則の境界

§2.2 で「雑談は絵文字使用可」と明示したが、Designer ペルソナ §10「絵文字なし（掲示板上は厳格）」と表現が揺れる。本 ADR §2.2 で「雑談に限り絵文字可 / formal 文書（ADR・歴史化メモ・コミットメッセージ）は引き続き不使用」を明確化。Designer ペルソナの記述更新は本タスクスコープ外（必要時に別 chore PR）。

### 5.5 ADR-0005 開いている論点の波及

ADR-0005 §5.1〜§5.5 の「開いている論点 5 件」のうち、§5.4 進捗共有頻度上限 は本 ADR §2.3 で「上限なし / ノイズ判定は PM 事後フィードバック」を確定した（ADR-0005 §5.4 (iii) を採択）。残る §5.1（コメント vs 独立ページ）/ §5.2（議論 → ADR 昇格トリガー）/ §5.3（議論の受領者粒度）/ §5.5（着手返答 SLA）は本 ADR で動かさない。

## 6. Superseded 詳細（ADR-0005 との差分）

ADR-0008 §2.3 の粒度明示パターンに倣い、ADR-0005 のうち本 ADR で Superseded する範囲を明示する。

### 6.1 ADR-0005 §2.1（採用案: ハイブリッド型 / 表）

**変更**: informal を 4 種から **5 種** に拡張（雑談を追加）。

| 旧（ADR-0005 §2.1） | 新（ADR-0009 §2.1） |
|---------------------|---------------------|
| informal 4 種（着手返答 / 進捗共有 / 質疑応答 / 議論） | informal **5 種**（着手返答 / 進捗共有 / 質疑応答 / 議論 / **雑談**） |
| 全 informal にタスクID 必須（議論のみ空可） | **雑談はタスクID・受領者すべて任意**（タイトルのみ必須） |

### 6.2 ADR-0005 §2.2（informal 4 種の用途定義 / 進捗共有）

**変更**: 進捗共有のログ単位禁止制約を撤廃。

- 旧: 「進捗共有: 中間状態の更新。「30% 完了」のようなログ単位ではなく、「設計の方針を A から B に変えた」「テスト 1 件を残してロジック実装完了」など **判断や状態遷移の単位** で投稿する。」
- 新: 「進捗共有: 状況共有が必要な任意のタイミングで投稿してよい。「30% 完了」「ファイル X 編集中」等のログ単位投稿も許容する。判断・状態遷移の単位を強制しない。」

### 6.3 ADR-0005 §3.7（ネガティブ・リスク / 緩和策 1）

**変更**: 「ログ単位ではなく判断・状態遷移の単位」緩和策を削除。

- 旧: 「**緩和策**: §2.2 で「ログ単位ではなく判断・状態遷移の単位」と明示。違反は PM が指摘」
- 新: 削除（本 ADR §2.3 で制約撤廃のため緩和策不要）。代わりに本 ADR §2.5 で「掲示板全投稿の 70% 超で可読性低下」をロールバック閾値として再定義。

### 6.4 ADR-0005 §5.4（開いている論点 / 進捗共有の頻度上限）

**変更**: 候補 (i)(ii)(iii) のうち (iii) を採択し論点クローズ。

- 旧: 「(ii) を本 ADR で採用したが、ノイズ流入が観測されたら (i) を導入する。」
- 新: 「(iii) **上限なし、ノイズ判定は PM の事後フィードバックに委ねる** を採択（本 ADR §2.3）。ノイズ流入が ADR-0009 §2.5 ロールバック閾値（70% 超）に達したら却下 (b) のタスク日次上限導入を再検討。」
